Prompts, tokens and context

A first quick tour of the ideas every later lesson leans on. Each one gets a full lesson in its proper stage; this page is the solid short version.

~15 minFull depth in Stages 2 and 4Python

1What generative AI is

Generative AI learns patterns from examples and uses them to create new content: text, images, audio, code. The output did not exist before the request; it is produced on the spot, conditioned on your input.

  • A spam classifier categorises an email into a fixed set of labels.
  • A generative model writes an email from your instructions.
!

A convincing answer can still be wrong. Fluency is what the model is trained for; factual accuracy is not guaranteed by it. Lesson 1.2 shows exactly why.

ExerciseIs an app that writes a birthday message generative AI? Why?

Yes, if a model composes the message: it produces new text conditioned on an instruction (name, tone, relationship), instead of choosing a label.

The subtle part: an app that only picks one of 20 pre-written templates is not generative, even if the result looks the same to the user. It is selection, closer to retrieval. What matters is how the output was produced, not what it looks like.

2What happens when you send a prompt

Your prompt→Tokenizer→Token IDs→Model→Next token↺Response text

A token is a piece of text: a whole word, part of a word, a space plus a word, or punctuation. The tokenizer maps text to integer IDs from a fixed vocabulary, and the model only ever sees those integers.

Given The capital of France is, the model predicts a likely next token, appends it, and repeats until it emits a stop token or hits a length limit.

Training vs using the model

During training, the model's parameters (weights) are adjusted. During normal use (inference), the parameters are frozen and your prompt is only context for that one request.

ExerciseYou paste a Python file and ask for a summary. Is the model retraining, or using the file as context?

Using it as context. The parameters stay exactly the same; the file just conditions this one response. Fine-tuning is a separate training job that updates parameters, and it is done ahead of time, not during a chat.

Extra · tokens are the unit of everything

Hosted APIs bill per token, usually with separate prices for input and output tokens. Context limits, rate limits and latency are all measured in tokens too.

A common rough rule for English is about 4 characters or ¾ of a word per token, but it varies a lot by tokenizer, language and content. Code, numbers and non-English text often use more tokens. Always count with the model's own tokenizer when it matters (Lesson 2.1).

3The context window

The context window is the maximum number of tokens a model can handle in one request. Depending on the provider, that budget covers the system instructions, conversation history, supplied documents, tool definitions and the generated output. Think of it as the model's working memory for that single call.

budget.py
# illustrative numbers, real limits depend on the model
context_limit = 8_000
instructions_and_history = 1_000
python_file = 5_000
reserved_output = 2_000

total = instructions_and_history + python_file + reserved_output
print(total <= context_limit)  # True, but with zero headroom

A long file can exceed the window even when the upload itself succeeded. The application, not the model, decides what goes in.

Why the chat "remembers"

The model keeps no memory between calls. A chat app re-sends the earlier messages every turn, so long chats slowly fill the window. When it is full, the app must drop, summarise or retrieve older parts. That is an application design decision.

+
Extra · capacity is not the same as effective use

Fitting in the window does not mean the model uses everything equally well. Research such as Lost in the Middle (Liu et al., 2023) found that models often use information placed in the middle of a long context less reliably than information at the start or end.

Bigger context also costs more and responds slower, because every input token is processed on every call. In practice, sending the right 3,000 tokens usually beats sending everything you have.

4Chunking and retrieval: a first look at RAG

ExerciseYour document is 20,000 tokens, the window is 8,000, and the question is about one function. What do you send?

Split the document and send only the relevant part: the function itself plus whatever is needed to understand it (imports, constants, and the helpers it calls), and leave the rest out.

You answered this correctly: split it, or take only the required part.
Chunking
Splitting a document into smaller pieces that can be stored, searched and sent independently.
Retrieval
Finding the chunks most relevant to a question, typically by keyword search, vector similarity, or both.
RAG · Retrieval-Augmented Generation
Retrieve relevant information first, put it in the prompt, then let the model generate an answer grounded in it.
manual_retrieval.py
question = "How does calculate_discount work?"

# picked by hand for now, later a retriever does this
context = """
def calculate_discount(price, percentage):
    return price * percentage / 100
"""

prompt = f"""
Explain the function using the supplied code.
If information is missing, say what is missing.

Code:
{context}

Question:
{question}
"""

The line "If information is missing, say what is missing" matters: it gives the model a sanctioned way to admit a gap instead of filling it with a guess.

Dependencies decide what a good chunk is

ExerciseIf the function calls get_tax_rate(country), should you include that helper too? Why?

Yes, include it. The function's output depends on the value get_tax_rate returns, so the function alone cannot be fully explained.

Without the helper the model only sees a call to an unknown function. It might say the rate is unknown (good), or it might invent a plausible rule like "uses 18% GST" (bad, and hard to spot). Including the helper, and the data it reads, lets the answer be grounded.

General rule: a chunk should carry what is needed to interpret it. For code, that means splitting along functions and classes and pulling in what they call.

★
Industry note

"Retrieved the right function but not its dependency" is one of the most common real RAG failures. It looks like a model problem (a wrong answer) but it is a retrieval problem. In Stage 4 we measure it separately with retrieval recall, so you can tell which half of the system failed.

Recap

  • Generative AI produces new content; what counts is how the output is produced.
  • Models see token IDs, not text. Tokens are the unit of cost, limits and latency.
  • Inference uses frozen parameters; the prompt is context for one call only.
  • The context window is a budget the application manages. Relevant beats long.
  • RAG = chunk, retrieve, then generate. Good chunks keep their dependencies.
