1.1 How AI, ML, deep learning and GenAI fit together

People use these words interchangeably, but they answer different questions. Getting the hierarchy straight makes every later design conversation clearer.

~20 minModule 1Concepts + industry

1Artificial intelligence

The broad field of building systems that perform tasks associated with intelligence: recognising speech, planning routes, understanding language, making decisions. "AI" says nothing about how it is done. Some AI systems simply follow rules a person wrote:

rules.py
def flag_transaction(amount, foreign_country):
    if amount > 100_000 and foreign_country:
        return "Review required"
    return "No rule triggered"

All of the behaviour comes from the programmer. Nothing is learned from data.

≈
SQL / Power BI analogy

This is a CASE WHEN column or a DAX IF. Precise and auditable, but every rule has to be thought of and maintained by hand.

2Machine learning

An approach inside AI where the system learns patterns from data. Instead of writing every fraud rule, you train on labelled legitimate and fraudulent transactions, and an optimiser adjusts the model's parameters to reduce prediction error.

The real difference: where the behaviour comes from

1
Rule-based: a person specifies the decision rules

In flag_transaction above, someone decided that "over 100,000 and foreign" means review. If fraudsters change tactics, the system will not notice until a person writes a new rule.

2
Machine learning: a training process learns the patterns from examples

You give the model thousands of past transactions with the correct label (fraud or not). Training adjusts its parameters until its predictions match those labels as closely as possible. Nobody writes the rule; the model finds combinations of features that separate the classes, including ones a person might never think of.

The trade-off: the learned behaviour is only as good as the data, and it is harder to explain than a written rule.

Summary of the comparison:

Rule-basedMachine learning
Where behaviour comes fromA person writes the rulesTraining learns them from examples
Changing behaviourEdit the codeChange data or objective, retrain
Unseen patternsOnly if a rule covers themCan generalise, can also fail in new ways
Explaining a decisionRead the ruleNeeds feature importance, SHAP, etc.

3Deep learning

A branch of ML that uses neural networks with many layers. Each layer transforms its input; training adjusts the weights by backpropagation so outputs match the objective better. The key practical advantage is that the network learns its own features from raw input (pixels, audio, text) instead of relying on hand-engineered ones.

Deep learning powers image recognition, speech recognition and text generation. It is not limited to generative AI: most image classifiers are deep but discriminative.

Systems that produce content: text, images, audio, video, code.

"Generative" describes what a system does. "Deep learning" describes how it is built. Most modern generative systems are deep learning models, but the two words answer different questions.

5Large language models

An LLM is a deep neural network (today almost always a transformer) trained on very large amounts of text to predict the next token. "Large" refers to both the parameter count (billions) and the training data. LLMs are one major type of generative AI; others generate images, audio or video.

Artificial intelligence
Any system doing "intelligent" tasks, including hand-written rules
Machine learning
Learns patterns from data
Deep learning
Multi-layer neural networks that learn their own features
LLMs
Transformer language models trained on huge text corpora

Generative AI cuts across this picture: it includes LLMs plus image, audio and video generators.

Related terms you will hear at work

Foundation model
A large model trained on broad data that can be adapted to many tasks. Most LLMs are foundation models.
Multimodal model
Takes or produces more than one kind of data, e.g. text and images in the same request.
Hosted (API) vs open-weight
Hosted: you call a provider's API and never see the weights. Open-weight: the weights are downloadable, so you can run and fine-tune the model on your own hardware. Big tradeoffs in cost, privacy and control (Module 2).

6Training vs inference

When you build an LLM application you almost always call a model someone else trained:

concept.py · not runnable yet
user_question = "Explain this sales trend"

response = existing_model.generate(
    instructions="Explain clearly and state any uncertainty.",
    input=user_question,
)

Your Python supplies instructions and data, calls the model, then processes the reply. Useful applications get built this way with no training at all.

This gives us two separate activities

1
Training: adjusting a model's parameters using data

This is where the model's knowledge and skills come from. It needs large datasets, a loss function, and a lot of compute. After training, the parameters are saved and frozen. For LLMs this is done by model providers, and it is the same idea as calling model.fit() on your own ML models, just at a vastly larger scale.

2
Inference: using a trained model to produce an output

The parameters do not change. You send input (your instructions, the question, any documents) and get output back. It is the equivalent of model.predict(). Every API call you make to an LLM is inference.

This is why pasting a Python file into a prompt does not teach the model anything permanent: it is inference, so the file is only context for that one call. Fine-tuning, by contrast, is a form of training and does update the parameters.

The full life of a model, from first training to your API call:

+When not to use an LLM Extra

In industry, a key skill is choosing the simplest tool that solves the problem. GenAI does not replace classical ML.

Hybrids are common: an LLM extracts structured fields from messy text (emails, tickets, contracts), then a classical model or plain SQL scores or aggregates those fields.

+Common misconceptions Extra

✕

"The model remembers our chat." The app re-sends history every call; the model keeps no state between requests.

✕

"Putting a document in the prompt teaches the model." Only for that request. The next request starts clean unless the app sends it again.

✕

"A bigger model fixes wrong answers." If the needed fact is not in the context or training data, a bigger model mostly produces a more fluent wrong answer. Fix the context first.

?Check yourself

Q1Is an image classifier built with a CNN "deep learning", "generative AI", both or neither?

Deep learning, but not generative. It is a multi-layer neural network (deep) that outputs a label (discriminative). This is the cleanest example of why the two words are different axes.

Q2Your manager asks for an LLM to predict monthly churn from a customer table. What do you say?

Start with a classical model (e.g. gradient boosting) on the table: it is cheaper, faster, gives calibrated probabilities and is easy to evaluate with AUC. An LLM could help elsewhere, e.g. turning free-text support tickets into features the churn model uses.

Q3Which layer of the stack is responsible for checking that the model's JSON is valid?

Guardrails / validation, in your application code. The model only produces text that looks like JSON; your code must parse it, validate it against a schema, and retry or fail cleanly (Module 2).

Recap

  • AI is the field; ML learns from data; DL uses multi-layer networks that learn their own features.
  • "Generative" is what a system does; "deep" is how it is built. They are different axes.
  • LLMs are transformer models trained to predict the next token on huge text corpora.
  • Training changes parameters; inference uses frozen parameters plus your context.
  • The model is one layer of an application stack. Pick the simplest tool for each problem.
