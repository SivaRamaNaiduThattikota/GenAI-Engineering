1.5 How language models got here, and how they are measured

You will build a real language model in twenty lines of Python, see exactly where it breaks, and follow how each step of history fixed one of those breaks, up to today's Transformers. Then you will learn perplexity, the basic score for a language model, and why benchmarks are only a first filter.

~30 minModule 1History + maths + Python

1The simplest language model: count what follows what

Definition: a language model is anything that assigns probabilities to the next token given the tokens before it (Lesson 1.2). It does not have to be a neural network. The oldest kind just counts.

An n-gram model looks only at the last n − 1 words. With n = 2, a bigram model, the next word depends only on the one word before it. To train it, count how often each word follows each other word in some text, and turn the counts into fractions.

bigram.py
from collections import Counter, defaultdict
import math

corpus = [
    "the invoice is paid",
    "the invoice is late",
    "the payment is late",
    "the payment is paid",
    "the invoice is late",
]

# count which word follows which
follows = defaultdict(Counter)
for line in corpus:
    words = ["<s>"] + line.split() + ["</s>"]
    for a, b in zip(words, words[1:]):
        follows[a][b] += 1

def p(b, a):
    return follows[a][b] / sum(follows[a].values())

print("P(next | 'is'):", {w: round(p(w, "is"), 2) for w in follows["is"]})

def perplexity(sentence):
    words = ["<s>"] + sentence.split() + ["</s>"]
    logs = [math.log(p(b, a)) for a, b in zip(words, words[1:])]
    return math.exp(-sum(logs) / len(logs))

for s in ["the invoice is late", "the payment is paid"]:
    print(f"perplexity of '{s}': {perplexity(s):.3f}")

# a sentence with an unseen pair
print("times 'was' followed 'invoice':", follows["invoice"]["was"])
print("so P('was' | 'invoice') =", p("was", "invoice"), "and the whole sentence gets probability 0")
Output · real run

Reading the code

  • <s> and </s> mark the start and end of a sentence. They let the model learn which words start sentences, and when to stop: the same idea as the special end-of-sequence token in Lesson 2.1.
  • zip(words, words[1:]) pairs each word with the next one: ("<s>", "the"), ("the", "invoice"), and so on.
  • follows is a table of counts. follows["is"] ends up as {"paid": 2, "late": 3}, because "is" was followed by "paid" twice and by "late" three times.
  • p(b, a) divides one count by the total for that row: P(late | is) = 3 / 5 = 0.6. That is the whole "training".

This is a genuine language model: you could generate text from it with the exact loop from Lesson 1.2. Its two weaknesses are what the rest of this lesson's history is about.

Two problems matter

1
Sparsity: anything unseen gets probability zero

"the invoice was late" is a perfectly normal sentence, but "was" never followed "invoice" in the training text, so the model gives it probability 0. One zero in the chain rule makes the whole product zero, and its log is undefined (which is why the code prints the count instead of computing a perplexity for that sentence).

The deeper issue: counting treats every word as an unrelated symbol. Seeing "the invoice is late" tells it nothing about "the bill is late", even though "invoice" and "bill" mean nearly the same. Classic fixes like smoothing (giving every unseen pair a small share of probability) hide the zeros but cannot create that understanding.

2
Short memory: only the last few words count

A bigram sees one word back. Making n bigger helps a little, but the number of possible word sequences explodes, so almost every 5-word sequence is unseen and sparsity gets far worse. In "The invoice that the customer from Hamburg sent last week is …", the word that decides "is" vs "are" is eight words back, out of reach.

2How each step fixed one problem

Seventy years of language modelling in one line: each major step fixed a weakness of the step before. The years on the axis are evenly spaced for readability, not to scale.

1
1948 · Counting (Shannon)

Claude Shannon's founding paper on information theory already generated "English-like" text from letter and word statistics: n-grams. Counting-based models then ran speech recognition and machine translation for decades. Weakness: sparsity and short memory, as you just saw.

2
2003–2013 · Words become vectors

Bengio and colleagues (2003) trained a neural network to predict the next word, and in doing so it learned a vector for every word. Similar words got similar vectors, so seeing "the invoice is late" now also raised the probability of "the bill is late". That fixed the "unrelated symbols" half of sparsity. word2vec (2013) made learning such word vectors, embeddings, fast and popular. Lesson 2.2 is about them.

3
2014 · Longer memory with RNNs, and attention

Recurrent neural networks (RNNs, especially the LSTM design from 1997) read text one token at a time while carrying a running summary, so in principle they could remember far back. In 2014, sequence-to-sequence RNNs reached strong translation quality, and attention was added: instead of squeezing the whole input into one summary, the model could look back at any input word when producing each output word. Remaining weakness: RNNs must process tokens strictly one after another, even during training, so they were slow to train on big data, and the running summary still faded over long texts.

4
2017 · The Transformer: attention only

The paper "Attention Is All You Need" dropped recurrence completely. Every position looks directly at every other allowed position through attention. That fixed both remaining problems at once: any word can use any earlier word directly, however far back, and training processes all positions in parallel (the causal-mask trick from Lesson 1.2), which suits GPUs perfectly. Every model in Lesson 1.4 descends from this design.

5
2018–2020 · Pretraining, then scale

GPT-1 and BERT (both 2018) showed the recipe of Lesson 1.4: pretrain one large model on lots of unlabelled text, then adapt it to many tasks. GPT-2 (2019, 1.5 billion parameters) and GPT-3 (2020, 175 billion) showed that simply making the same design bigger kept making it better, and that a big enough model could do new tasks from a few examples in the prompt.

6
2022 onwards · Assistants, open weights, reasoning

InstructGPT (early 2022) applied SFT and RLHF to make the model follow instructions, and ChatGPT (November 2022) put that in front of the public. In 2023, Meta's Llama started a wave of strong open-weight models. From 2024, reasoning models added RL on checkable tasks (Lesson 1.4). The core is still the 2017 Transformer trained on next-token prediction.

3Scaling laws: why bigger kept working

In 2020, researchers at OpenAI (Kaplan and colleagues) measured something useful: a language model's test loss falls smoothly and predictably as you increase three things together: the number of parameters, the amount of training data, and the compute spent. The relationship is a power law, which looks like a straight line when both axes use a logarithmic scale.

Two details matter

1
Predictable means plannable

Because the line is straight, a lab can train small models cheaply, fit the line, and predict how good a model ten times bigger will be before spending the money on it. This is a large part of why companies were willing to fund training runs that cost tens of millions of dollars.

2
Data matters as much as size (Chinchilla, 2022)

DeepMind's Chinchilla work found that many big models of the time were under-trained: for a fixed compute budget, it is better to use a smaller model on more data. Their rule of thumb was roughly 20 training tokens per parameter. Chinchilla (70B parameters, 1.4 trillion tokens) beat their earlier 280B model. Since then, models are often trained far beyond 20 tokens per parameter, because a smaller model that is cheaper to run pays off over billions of inference calls.

!
What scaling laws do not say

They predict loss, the next-token score. They do not promise that a specific skill, like correct arithmetic or following your company's rules, appears at a given size, and they say nothing about factual accuracy on your data. That is still measured task by task (section 5).

4Perplexity: the basic score of a language model

The training loss from Lesson 1.2 is the average negative log-probability the model gives to the true next tokens. Perplexity is the same number made easier to read: take e to the power of the average loss.

perplexity = exp( −(1/N) ∑i=1N log P(ti | t<i) )N = number of tokens scored · lower is better · the minimum is 1
ppl.py
import math

# the per-token probabilities from Lesson 1.2's log-space example
step_probs = [0.9, 0.7, 0.8, 0.6]
nll = -sum(math.log(p) for p in step_probs) / len(step_probs)
print("average negative log-likelihood:", round(nll, 3))
print("perplexity:", round(math.exp(nll), 3))

# a model that knows nothing: uniform over a 200,000-token vocabulary
V = 200_000
print("uniform model perplexity:", round(math.exp(-math.log(1 / V))))
Output · real run
average negative log-likelihood: 0.299
perplexity: 1.349
uniform model perplexity: 200000

Two ways to read the number

1
The effective number of choices

A model that spreads its probability evenly over k options at every step has perplexity exactly k. So perplexity says: "on average, the model was as unsure as if it had to pick among this many equally likely tokens". A perplexity of 1.35 means it was nearly certain; the know-nothing uniform model, guessing among 200,000 tokens, scores 200,000. Our bigram scored 1.23 and 1.44 on sentences from its own tiny training text, which is easy; on new text it would score infinitely badly because of the zeros.

2
Only comparable under the same conditions

Perplexity is per token, so it depends on the tokenizer: a model with bigger tokens makes fewer, harder predictions per sentence, and its perplexity is not directly comparable to one with smaller tokens. It also depends on the test text. Compare perplexities only for the same tokenizer on the same held-out text, which in practice means comparing versions of your own model, such as before and after fine-tuning on your domain.

≈
ML analogy

Perplexity is to a language model what log loss is to your classifiers: a good training and comparison signal, computed from probabilities, that says nothing directly about whether the business outcome is right. A model with lower perplexity on general web text can still be worse at extracting your invoice fields.

+How models are compared today, and why your test set wins Extra

For chat models, perplexity is rarely quoted. Comparisons use benchmarks: fixed sets of tasks with checkable answers.

K
Knowledge and reasoning
Multiple-choice exams across many subjects. MMLU (2020), 57 subjects from law to physics, was the standard for years.
C
Code
Write a function, run hidden unit tests. HumanEval (2021) started this style; newer sets use real repository issues.
H
Human preference
People compare two anonymous answers and vote; votes become a rating, like a chess ranking. Chatbot Arena (2023, now LMArena) popularised this.

Three limits matter

1
Contamination

Benchmark questions are published on the web, and the web is the training data. If a model has seen the test questions during pretraining, its score measures memory, not skill. Labs try to filter this, but it is hard to rule out.

2
Saturation

Once top models score above about 90%, a benchmark can no longer tell them apart, and the field moves to a harder one. A benchmark from three years ago may say little about today's models.

3
It is not your task

No public benchmark contains your documents, your users' questions, or your definition of a good answer. A model that ranks third on a leaderboard can be the best for your extraction job, or the cheapest one that is good enough. The test set and checks from Lesson 1.3 are the only scores that decide what you ship.

?Check yourself

Q1In the bigram model, why does "the invoice was late" get probability 0, and which historical step addressed the deeper cause?

"was" never followed "invoice" in the training text, so its count and probability are 0, and one zero makes the whole chain-rule product zero. The deeper cause is that counting treats words as unrelated symbols. Neural language models with word vectors (2003, then word2vec in 2013) fixed that: similar words get similar vectors and share what is learned about them.

Q2What two limitations of RNNs did the Transformer remove?

RNNs process tokens strictly in sequence, even in training, which is slow on large data; and their running summary fades over long distances. The Transformer lets every position attend directly to every allowed earlier position, and trains all positions in parallel using the causal mask.

Q3A model assigns probability 0.25 to every true next token in a test text. What is its perplexity?

4. The average negative log-probability is −log 0.25 = log 4, and exp(log 4) = 4. It is as unsure as choosing among four equally likely tokens at every step.

Q4Model A has perplexity 8 on your text and model B has 11, but they use different tokenizers. Can you say A is better?

No. Perplexity is per token, and different tokenizers cut the same text into different numbers of tokens of different difficulty. Compare them on the task instead, with your own test set.

Q5What did Chinchilla change about how models are trained?

It showed many large models were under-trained: for a fixed compute budget, a smaller model trained on more data does better, at roughly 20 tokens per parameter. Today models are often trained on even more tokens than that, because smaller models are cheaper to run at scale.

Q6Your manager picks a model because it tops a public leaderboard. Give two reasons to test it on your own data first.

Any two of: the benchmark may be contaminated or saturated; it does not contain your documents, questions or quality criteria; a cheaper or faster model may be good enough for your task; leaderboard tasks may not reflect your format or language requirements.

What to retain from this lesson

A language model is any next-token probability model. Counting models fail on unseen text and long-range context; word vectors, attention and finally the Transformer fixed those problems, and scaling the Transformer did the rest. Perplexity scores a language model; your own test set scores an application.

  • n-gram models count what follows what; they assign zero to anything unseen and see only a few words back.
  • Neural LMs and word2vec gave words vectors; RNNs and attention extended memory; the Transformer gave direct access to all context and parallel training.
  • Scaling laws: loss falls predictably with parameters, data and compute; Chinchilla showed data matters as much as size.
  • Perplexity = exp(average negative log-likelihood) = the effective number of choices; compare only with the same tokenizer and test text.
  • Benchmarks are a first filter: contamination, saturation and task mismatch limit them. Your own test set decides.
